# Security policy

ParanoID is in the inception phase and has no supported production release.

## Reporting a vulnerability

Do not publish a suspected vulnerability in a public issue. Contact the
repository administrators through an agreed private channel and include:

- affected component and revision;
- reproduction steps or proof of concept;
- expected security impact;
- any suggested mitigation;
- whether the issue is already public.

A dedicated security contact and GitHub private vulnerability reporting must be
configured before the repository becomes public or any production release is
distributed. Until then, this private repository is not a security support
channel for deployed systems.

## Disclosure principles

- Acknowledge receipt and establish a private coordination channel.
- Validate severity and affected versions before promising a timeline.
- Prepare a fix, tests, advisory, and upgrade instructions together.
- Credit reporters unless they request anonymity.
- Do not claim a vulnerability is fixed without reproducible verification.
