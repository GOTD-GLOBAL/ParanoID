## Verified correct

- **Geometry/centering.** Content boxes are 19×12 dp for all three states (queued circle centred at 9.5,6 r4.5; ticks span x 1–18, y 2–10, both single and double forms centred on 9.5). `translate((w−19·d)/2, (h−12·d)/2)` then `scale(d,d)` puts every state on the view centre, and stroke (0.75 dp half-width) stays inside the 24×18 dp box — no clipping at either density.
- **fontScale independence is real, not just asserted.** `ReceiptMark` reads `displayMetrics.density`, never `scaledDensity`, and `strokeWidth` is set pre-scale so it renders as 1.5 dp. The instrumentation's pixel-equality check under fontScale 1/2 therefore tests the property it claims.
- **Hint gating.** `receiptHintEarned` requires non-empty `own` and an own-authored row with `delivered` true; incoming delivery, server acceptance, empty/missing dialog and empty `own` all return false, matching the smoke test. No mutation of the passed view.
- **No stale card.** `renderHistory`'s signature now includes `ReceiptHint.isPending`, and the `delivered` flag flip changes `messages.toString()`, so both "hint becomes earned" and "hint dismissed" force a repaint. `apply()` updates the in-memory prefs map synchronously, so the immediate `renderHistory(false)` after `dismiss()` sees `false`.
- **Precedence and layout preserved.** The blocked/verified `else if` chain is untouched; the mark still occupies the `side` slot under `side.setGravity(Gravity.END)`, and the bubble footer keeps the timestamp as a separate view (time still visible independently of the mark).
- **No privacy/wire surface.** `ReceiptHint` writes one boolean to an app-private prefs file, no account IDs, text or timestamps; backup-disabled manifest unchanged; no core/wire/crypto/snapshot changes. `MessagePresentation` remains Android-free (only `java.*` + `org.json`), so `test_receipt_presentation.py` really is a host-JVM execution, not a source grep.
- **Probe isolation.** `targetPackage` is the UUID-named probe itself, so `getTargetContext()`/`prefs.clear()` cannot touch messenger data; manifest requests no `INTERNET`; the serial guard rejects non-`emulator-` targets; uninstall runs in `finally`.
- **Checked-exception handling is consistent across both toolchains:** `org.json`'s `JSONException` is unchecked in json-20240303 (host smoke needs no `throws`) and checked on `android.jar` (the instrumentation declares `throws Exception`). Both compile.

## Non-blocking findings

1. **`ReceiptMark` has no `onMeasure`** (`ReceiptMark.java:23`). `setMinimumWidth/Height` only take effect under `MeasureSpec.UNSPECIFIED`; the default `getDefaultSize` returns `specSize` for `AT_MOST`. Safe today because both call sites pass explicit `box(24,18)`, but a future `WRAP_CONTENT` use would silently expand the view to the full row width. Overriding `onMeasure` with `resolveSizeAndState(getSuggestedMinimumWidth(), spec, 0)` would make the declared minimums honest.
2. **Probe APK is signed with the retained production keystore** (`test_receipt_android_runtime.py:50`). Package name is random and the artifact is temp-dir-scoped and uninstalled, so it cannot be installed over `global.paranoid.messenger`; still, a throwaway debug keystore would be sufficient for an emulator probe and would avoid producing release-signed artifacts for synthetic packages (relevant if the app ever declares `signature`-level permissions or a `sharedUserId`).
3. **`installed = True` is set after `adb install` returns** (`test_receipt_android_runtime.py:58`). If install fails mid-way the `finally` skips uninstall. Setting the flag before the call is strictly safer.
4. **Javadoc overclaims** on `receiptHintEarned`: "authenticated own-message delivery" — the function compares `dialog.own` to `author` and reads the `delivered` flag; there is no authentication step here. Suggest "own-authored message the client has recorded as delivered".
5. **`ReceiptViewInstrumentation.java` sits in `test/` but declares `package org.paranoid.text`** though it only uses public API. Worth confirming no build step globs `test/**/*.java` into the app DEX; explicit compiles in `build.sh` suggest it does not.
6. **Docs/CHANGELOG ordering.** The merged `2026-09-22` Solana and `2026-09-21` sections were inserted *below* the receipt entry in both `CHANGELOG.md` and `docs/project/current-state.md`. If the receipt entry above them is dated `2026-09-18` (as `docs/clients/android/receipt-presentation.md` `last_reviewed` implies), the files are no longer reverse-chronological. Cosmetic, but easy to fix while the conflict resolution is fresh.
7. **Test slicing is positional.** `test_ui_contract.py` splits on `private void receiptHintCard(` / `private void empty(`; reordering methods breaks the slice. It fails loudly (IndexError / failed assertion) rather than silently passing, so this is brittleness, not a hole.
