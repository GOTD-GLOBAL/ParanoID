## Audit priorities — source/test/evidence correspondence

1. **Native E2EE authority.** `PlainV1` and `CallV1` are `deny_unknown_fields` with exact kind/body validation (`clean_service.rs:86-108`, `voice_v1.rs:26-82`); the signed intro-v2 wrapper binds account/device/credential/contact/recipient/realm-pin/channel/id/inner-digest (`intro_v2.rs:73-158`). SDP validation enforces exactly one `m=audio` DTLS-SRTP section, one Opus/48000/2 mapping, one fingerprint (SHA-256 only, exact 64-hex binding), one ICE context, `sendrecv` only, ≤16 candidates ≤512 B each, SDES `a=crypto:` rejected, ≤6144 B SDP inside the ≤16 KiB frame, offer digest bound to exact bytes. Standard optional attributes (`extmap`, `ssrc`, `rtcp-fb`, `msid`) are tolerated without granting authority — the real M150 offer in `media-direct-8` passes this validator, and `native-real-sdp-captures` validated all four captured offers/answers through real Olm with substitutions rejected. Unknown call peers are rejected before any commit (`unknown_call_peer`, `clean_service.rs:585-587`) and the whole candidate state — including consumed prekeys and transient contacts — is discarded on rejection because receive operates on a deep copy (`clean_service.rs:644-674`). Blocked peers rejected at entry. Test `unknown_and_blocked_call_controls_cannot_allocate_or_mutate_crypto_state` covers this.

2. **Replay and storage.** Calls commit ratchet/cursor but insert no Event/history/receipt rows (`clean_service.rs:601-616`); heartbeats cannot exhaust the 1000-event text ledger (test: 20 maximum calls, 3700 real Olm controls). The consumed-fallback guard compares `PreKeyMessage.session_id` against all retained sessions after failed decrypt (`clean_service.rs:508-514`), with dedicated tests `higher_sequence_replay_of_consumed_call_prekey_never_recreates_a_fallback_session` and `retained_session_id_identifies_consumed_reusable_fallback_prekey` (the latter pins actual vodozemac behavior). Below-cursor and conflicting-sequence replays refused; exact text duplicates return `exact_duplicate`; sessions capped at 8, never evicted. 62 supported native tests pass including the 14 voice tests (signaling evidence only, as claimed); the 14 historical failures reproduce with the **exact PR18 names**, zero new failures (`core-historical14-final.json`: `new_failure_names: []`).

3. **Commit and transport authority.** The transient event is `CallEvent {account, channel, body}` — channel is additive authenticated metadata over the design sketch, not new wire authority (`clean_service.rs:156-161`). `SelfServiceClient.apply` saves the sealed snapshot (with byte readback and directory fsync in `TextEngine.persist`) **before** adopting state and only then dispatches `call_event`; failed save sets `broken` and triggers `authorizationLost`, terminating media. Send completion fires only from `accepted()` after validated server acceptance (id + sequence ≥1) following durable enqueue. Native admission requires existing peer outbox `< 16` (`clean_service.rs:398-400`) — 16 pending calls, 384 text slots reserved, matching the corrected arithmetic; test `call_admission_preserves_normal_text_outbox_capacity_and_numeric_bounds`. One heartbeat pending at a time (`heartbeatPending`), controls enqueue only while online, no offline heartbeat backlog, no re-signing/removal of immutable queued ciphertext.

4. **Freshness, consent, confirmed authorization failure.** Volatile nonces and slots live only in `CallController` memory ("No call authority is loaded from storage"); v8-compat evidence confirms no call resumes across reopen. Caller media starts only on matching `ready` with permission; receiver media only on explicit Answer + permission; generation tokens reject stale/cross-call callbacks; wall/mono skew >5 s ends negotiation; first-seen expired and future-dated (>5 s) controls rejected. Bounds all present: 45 s TTL, 10 s ICE recovery, 30 s silence, 15 min max, knock limits, 64 tombstones. The 75 s + skew revocation bound is stated honestly in `voice-v1.md`. The 401 semantics are exactly as specified: `sessionCall` retries the same immutable operation once with a fresh signed nonce on the first 401 (`RealtimeLoop.java:124`) without reaching `authorityFailure`; a second 401 propagates and stops call authority; 401s outside that path stop immediately. **Actual pinned-TLS evidence, not just source:** `realtime-authority-tdd.json` RED shows [401,200] with one false `authorizationLost`; GREEN shows [401,200] → zero stops and isolated real revoke [401,401] → exactly one stop with pending preserved and no plaintext.
