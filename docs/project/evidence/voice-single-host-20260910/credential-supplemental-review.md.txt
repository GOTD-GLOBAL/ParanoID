## Review B — proposed relay-runtime-only credential contract, Gate 2: **CONDITIONAL (implementation withheld)**

### Gating fact: A has not observed the layout
The prerequisite "If A actually observes root0440 and unchanged descriptor rejection" is **not yet satisfied**. Both `result.json` records stopped at `success_marker_not_observed` with the *source* descriptor `uid 0, mode 0o400` (`runtime/result.json:16-21`) — the **delivered copy's** owner/mode is unmeasured, and the corrected run used the old bare-string helper (`corrected-once/.../result.json:22`, `helper_output: "credential_validation_failed\n"`), so no stage or descriptor was captured. The finding itself states this is `NOT_MEASURED` (`credential-compatibility-finding.md:21-46`). Gate 1 exists precisely to capture it and is `NOT_RUN` (`validation.json:12`). **Therefore Gate 2 conditional approval remains contingent on the Gate 1 diagnostic actually showing `root:0440` and the `credential_descriptor` rejection.** The design's own sequencing agrees ("Only after Gate 1 confirms the relevant layout and fresh Fable approves…", `credential-acl-design.md:85`).

### The recognizer design is the right shape
Option B (`credential-acl-design.md:152-172`) correctly targets the Linux `system.posix_acl_access` ABI: LE `__le32` version-2 header + 5 × 8-byte `{__le16 tag, __le16 perm, __le32 id}` = exactly 44 bytes, one bounded `fgetxattr`, reject any other length/`ERANGE`/`ENODATA`/`ENOTSUP`, decode with `struct`, compare typed entries. The five-entry file candidate (`:120-127`) — `USER_OBJ r`, `USER=euid r`, `GROUP_OBJ 0`, `MASK r`, `OTHER 0`, all non-USER ids `0xffffffff` — matches systemd v255's `fd_add_uid_acl_permission` output and the canonical ascending tag order on disk. The **core safety property is correct**: `GROUP_OBJ == 0` and `OTHER == 0` are what distinguish a legitimate named-user ACL delivery from "an arbitrary root-owned group-readable file," and "Never infer the named-user grant from stat mode alone" (`:130-131`) is the right rule. Pinning the production entry to `CREDENTIALS_DIRECTORY == /run/credentials/paranoid-turn.service` and `RUNTIME_DIRECTORY == /run/paranoid-turn`, with fixtures barred from the production entry (`:93-98`), correctly prevents the ACL-accepting reader from being pointed at attacker-influenced paths. Keeping the generic `read_secret` 0400/0600 semantics (`runtime.py:24-27`) and the source/alpha/Rust guards unchanged, and rejecting Option C workarounds (`:173-177`), is the right boundary.

### Security corrections that must be in the implementation
1. **libc binding:** use `ctypes.CDLL(None, use_errno=True)` (already-loaded libc), never `find_library`/ambient search (design says so — enforce it); set `restype = c_ssize_t`, `argtypes = [c_int, c_char_p, c_void_p, c_size_t]`; verify the symbol exists and fail closed if absent; treat any return `< 0` or `!= 44` as reject, using `get_errno()` only for diagnostics.
2. **Explicit little-endian struct** (`<I`, `<HHI`), not native `=`.
3. **Exact id checks:** `USER` entry id `== os.geteuid()` (unsigned, and `euid != 0`); `USER_OBJ/GROUP_OBJ/MASK/OTHER` id `== 0xffffffff`. Perms exactly `4/4/0/4/0` (file) — reject any write(2)/exec(1) bit on any entry.
4. **fd-only operations:** `fgetxattr`, `fstat`, and `read` all on the same fd opened `O_RDONLY|O_NOFOLLOW|O_NONBLOCK|O_CLOEXEC`; open each ancestor with `dir_fd=parent` + a single non-`/` component + `O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC`, validating root-owned, `mode & 0o022 == 0`, no setuid/setgid/sticky at each level. This closes symlink/TOCTOU on the path; the post-read dev/inode/type/uid/gid/mode/nlink/size/ctime recheck (`:135-137`) is good defense-in-depth.
5. **Confirm the generic reader still rejects the 0440+ACL file** as an explicit RED case, and that source-master/source-copy/installer, alpha issuer, and Rust issuer guards remain byte-unchanged (must be re-verified at final review — those files are not in this tree).

### Sharpest technical finding: the directory candidate is unverified and probably wrong
The file candidate (`USER_OBJ = 4`) is self-consistent: base `0400` + named-user ACL → stat `0440`, `USER_OBJ = r`. But the **directory** candidate — "root-owned `0550` … permissions `5/5/0/5/0`", i.e. `USER_OBJ = 5` (`:114,133`) — assumes systemd creates the per-service credentials directory with base mode `0500`. If systemd instead creates it `0700` (the more common case) and then adds `user:svc:r-x` + mask, the stat shows `0750` with `USER_OBJ = 7` (owner rwx), not `5`. Gate 1's numeric descriptor **does not measure ACLs at all** (by design), so this cannot be resolved by running Gate 1. A recognizer hard-coded to `USER_OBJ = 5` would fail-closed against a real `USER_OBJ = 7` directory (safe, but wrong), so the directory branch must be corrected against the *measured* delivery, not the source-derived guess. Do **not** broaden it to accept both values speculatively.

### Simpler exact-safe alternatives worth weighing
- **Prefer the chown-fallback path where it applies.** systemd chowns the copy to the service UID when ACLs are unavailable; that yields a `euid`-owned `0400` file that the **existing** `read_secret` already accepts (`runtime.py:25-26`) with **no new code**. It cannot be forced on an ACL-capable `/run` tmpfs, so the recognizer is still needed for the default case — but the euid-owned `0500` dir / `0400` file branch (`:113`) should stay the primary, ACL-free path and be tested as such.
- **Do not adopt libacl (Option A)** unless Fable prefers it: it enlarges the pinned six-library relay closure and still needs an independent bounded precheck. The xattr recognizer, with the corrections above, keeps the new trusted surface smaller and on a documented ABI. Either way, do not combine two readers that accept different ACL sets.

### Evidence order is acceptable; a further review is required after observation
The design's order — offline strict RED/GREEN against *synthetic* `setfacl` fixtures, then **one** separately bounded inert primitive matrix that exercises real system/user-manager delivery (`:180-201`) — is correct: the real delivered ACL is only truly confirmed by that matrix, which fails-closed and stops if reality diverges. **A short further design confirmation is nonetheless required after Gate 1 and before freezing GREEN fixtures**, precisely because: (a) Gate 1 yields owner/mode only, not the ACL entry set/mask/count; (b) the directory branch above is likely mis-specified; and (c) building GREEN against an unverified ACL risks encoding a wrong recognizer. Then, as the design already mandates (`:203-209`), the final change reopens `runtime.py` and its manifest hash and requires the runtime credential contract/threat/runbook updates, a TURN kit rebuild/re-pin, and a fresh final Fable code/artifact review.
