## Recognition, paths and locking

Require real root-owned private coordinator state `/var/lib/paranoid-single-host` (0700); root-owned kit/release sources not writable by service accounts. Verify each ancestor and every file with lstat/no-follow/open/fstat, regular type, one link, expected owner, mode, size and hash. Reject symlink ancestors, hardlinks, devices, duplicate archive paths, extra package members, reused IDs with different bytes, unrecognized preexisting destinations and unsafe extraction. Only immutable installed release directories are shared read/execute. Do not follow a service-user path while privileged to write content; message-owned mutations happen only after dropping to the verified UID through the narrow worker. Trusted dedicated owner is a prerequisite, not a hostile-user sandbox.

Mutations take a no-follow private root global flock and a durable transaction journal. The UID worker independently holds alpha's existing operator lock for its whole stop/switch/config/unit/start or rollback transaction; it calls the unlocked `switch_v2_locked` primitive, avoiding nested-lock deadlock. Existing lifecycle lock remains owned by its process; no lock file is unlinked. Preflight repeats under locks and compares recognized host/config/network/kit digests with approved plan. Drift stops before mutation. Cross-controller concurrent alpha maintenance therefore cannot race the coordinator's message transaction.

Archive handling reuses strict bounded regular-file semantics but validates the combined kit allowlist independently. Staging uses exclusive private directories, fsynced files and directory entries, immutable hash identities and atomic rename. Never overwrite unknown files. The root journal captures old release/config/unit/network identities and baseline enable/active/linger state before intent. Sensitive previous config bytes are retained only privately under their owner (or root-private transaction state), never in public evidence. Resume is permitted only from a recorded phase with exact matching artifacts/state. An ambiguous interrupted phase fails stopped with a transaction ID and an explicit rollback command; it never assumes success or resets state.

## Egress and ingress policy

Use an exclusive nftables `inet paranoid_voice` table with an OUTPUT base chain filtering only the verified numeric relay UID, before ordinary accept chains; all other UIDs return unchanged. Rules are root-owned, exact hashed, loaded atomically as one nft transaction; never flush unrelated tables/chains or modify default policies. The dedicated table name must be absent or match recorded exact prior state. IPv6 is denied for relay UID in addition to the existing AF_INET-only unit. Resolve/verify host-owned addresses locally; do not probe a metadata endpoint or neighboring service.

For relay UID, first allow only own public-IP UDP packets with source AND destination ports40000–40015 (same-host relay-to-relay media). Then deny every destination classified as a local host address (`fib daddr type local`), preventing access to 80/443/38443/34781/other services on any host address. Deny non-public/bogon IPv4 destinations consistent with reviewed coturn peer ACL. Allow public-address UDP replies from listener34781, established public-address TCP replies from listener34781, and public-address UDP relay packets from40000–40015. Final drop for relay UID. This default deny constrains outbound sockets; it does not remove a CLI listener or its authorization surface. The effective CLI-closure gate remains mandatory. Reply-versus-peer distinction uses listener/relay source ports; actual effective packet tests must demonstrate no own-host or private-range bypass and working same-relay selected candidates. Root must review whether any necessary control packet is missing; no broad allowance may be added merely to make a test pass.

Inbound changes are only three exact UFW allow tuples on the explicit interface and destination IP: TCP34781, UDP34781, UDP40000:40015, with unique coordinator comments. Existing TCP38443 stays unchanged in existing-v8. Fresh requires its explicit TCP38443 rule included in its own reviewed plan. Require active recognized UFW/backend/default behavior and no conflicting preexisting rule ownership. No UFW enable/reset/default/whole-file replacement. Record exact added tuple and baseline absence; rollback deletes exact owned tuples, never mutable rule indices or another operator's matching rule. Because direct nft accept cannot bypass a later UFW deny, ingress is not falsely represented as handled by the dedicated output table.

Install egress before starting relay; add inbound TURN rules only after installed hashes, credential check and no-public-exposure local health are established and all predeployment gates already pass. If activation fails, remove owned ingress first, stop relay, disable issuer/recover message service, then remove only owned egress once relay is confirmed stopped. Retain egress if stop cannot be confirmed. Never expose the candidate merely to discover whether prerequisite tests pass.

## Coordinated phase order and failure semantics

1. Repeat preflight under global lock; verify exact mandatory acceptance and plan. Record pristine/recognized baselines and durable intent.
2. Stage verified immutable message/relay/installer releases, dedicated identities and secret sources without starting relay or adding ingress. Check actual generated system/user units; perform launcher check without listener or secret-bearing stdout.
3. Run UID message transaction under alpha operator lock: recognize unit/config/cluster/TLS; stop only message unit; take actual encrypted restore-verified current backup via existing v2 primitive; select compatible candidate through switch_v2_locked while config bytes remain exactly unchanged; only after successful pointer cutover preserve all old config fields and add the versioned voice object; atomically generate/install prospective unit; reload its user manager; start and run pinned-TLS/DB health. Keep old code/config/unit references. No `replace-v2`, schema migration, DB restore-over-current or fresh command exists in this existing-v8 branch.
4. Install/verify effective dedicated egress; install named relay+policy units; start relay with ingress still closed, check actual credential/lifecycle/readiness allowed by approved predeployment procedure. Only after success add exact ingress, enable intended boot persistence and perform permitted own-synthetic external acceptance.
5. Verify retained TLS/key/cluster/config-base identities, intended installed package/unit/network hashes, current binaries/health and baseline neighboring unit/port inventory without traffic to neighbors. Commit active state only on all required postflight results.

Any exception or signal after intent triggers bounded recovery based on recorded phase, never success exit. Existing mode restores exact journaled previous config bytes (voice-free on deployed v8, never a v:0 invented variant), unit and same-data previous release after stopping only named message unit and relay; old binary receives disabled issuer config, all new rows remain. Recovery may not overwrite drifted/unrecognized files; such a case keeps affected units stopped, ingress removed where owned and egress retained if needed, with precise transaction diagnostics. Ordinary nonzero exits and SIGINT130 remain non-success. Power-loss recovery reads durable intent and refuses automatic destructive cleanup. A repeat apply with exactly committed plan verifies installed identities and returns already-applied without backup/secret rotation/service restart; changed intent requires explicit update. Update preserves secret/TLS/DB and retains one exact transaction target for rollback. Rollback reverses only owned changes and preserves new current DB contents; it is not an old dump restoration.
