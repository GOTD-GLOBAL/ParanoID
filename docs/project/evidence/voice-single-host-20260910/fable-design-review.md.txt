## A. Unified installer/network design — CONDITIONAL

The design is fundamentally sound and consistent with the code it builds on. I verified the load-bearing claims against `alpha.py`: the two-lock scheme is real and deadlock-free as described (worker holds `operation.lock` from `v2_operation_lock` at `alpha.py:942` and calls `switch_v2_locked` at `alpha.py:1112`, which takes only `lifecycle.lock` internally); the candidate alpha's `unit()` renderer already emits the `LoadCredential=voice-turn-secret:{root}/voice-turn/issuer.secret` line conditionally on the voice config (`alpha.py:782`), so the "only its LoadCredential line is added" claim is achievable through the reviewed renderer rather than byte-patching; `config()`/`turn_settings()` (`alpha.py:105-152`) enforce the exact voice object and the 64-hex credential contract matching `runtime.py`; and `reviewed_v2_ip` (`alpha.py:503`) pins production to `157.180.49.125` while permitting loopback for fixtures. The egress rule ordering (own-public-IP UDP 40000–40015 allow before the `fib daddr type local` deny, then bogon deny, then listener/relay-port allows, then final drop), UFW-only ingress with exact owned tuples, the ingress-last/egress-first activation ordering, no force/skip-gates flags, and the honest "acceptance doc is an operator-verified audit record, not cryptographic proof" framing are all right. Implementation under current authority means local code plus offline RED/GREEN, package verification and compile checks only — which the draft itself states.

Concrete findings that must be resolved in the design before implementation:

1. **Rehearsal circularity (the blocker you asked me to resolve).** Production `apply` demands an acceptance document whose entries include the completed coordinated fresh/update/rollback rehearsal — but the first disposable rehearsal is itself an `apply` and has no completed rehearsal gate to cite. Resolve it structurally, not with flags: make the acceptance schema define **per-profile required gate lists** at design time. The fixture profile (e.g. `paranoid-single-host-fixture-v1`) requires only the gates that legitimately precede any mutation anywhere — this design review, the RED/GREEN offline suite, kit/artifact hash verification — and by definition excludes the rehearsal gate it exists to produce. The production profile requires the full list, including rehearsal evidence bound to the fixture-profile hashes. This is not a skipped gate and needs no synthetic PASS receipt: the two profiles have different, fixed, reviewable gate sets, and no runtime input can move a gate between them. The fixture profile must be structurally incapable of live/public targets: loopback/owned-fixture addresses only (alpha already permits loopback), distinct unit/account names, refusal to run where production markers (`/var/lib/paranoid-single-host`, `/etc/paranoid-turn`, production unit names) exist, a distinct profile ID embedded in every artifact, and production `preflight`/`apply` rejecting any fixture-profile artifact or acceptance entry. The fixture harness must also carry an explicit denylist of the previously denied security work: no coturn packet/expiry/ACL tests, no namespaces, no shared firewall mutation.
2. **Missing runtime prerequisite: Python `cryptography`.** The implementer is correct. The backup path the coordinator depends on imports it (`alpha.py:974`, `alpha.py:1016`), but the draft's prerequisite list (Python 3.12, OpenSSL, PG16, systemd, nft/UFW) omits it. Add it to the kit prerequisites and runbook, and make `preflight` verify importability of the exact AESGCM/Cipher API before any mutation — an apply that discovers this mid-transaction fails at the worst moment (during `backup_v2` with the message unit stopped).
3. **`cli=0` must be verified against the pinned coturn source at design time.** `turnserver.conf.in:17` uses `cli=0`, the tests assert exactly that and the absence of `no-cli` (`test_runtime.py:45-46`), and a prior design gate prescribed it (`voice-turn-threats.md:39`). But `no-cli` is coturn's historically documented disable directive, and the behavior of an unrecognized directive (startup failure versus silently ignored with the CLI left listening on 127.0.0.1:5766) is exactly the wrong thing to discover live. Since the pinned source (coturn 4.18.0, `inputs.json`) is offline in the kit inputs, the implementer can and should confirm `cli` is a recognized boolean option in that version's option table before implementation. Independently, correct the draft's claim that the egress table "also blocks coturn CLI" — the nft table filters relay-UID *output* only; it would break CLI replies but does not remove the listener or its auth surface. The effective 5766-closure gate stays mandatory and NOT RUN either way.
4. **The relay-unit dependency change re-opens the pinned TURN package.** Adding `Requires=`/`After=` on the egress-policy oneshot to `paranoid-turn.service.in` changes pinned package bytes, so it requires a package rebuild, manifest re-pin and review — plan that explicitly. Also specify the policy unit precisely: `RemainAfterExit=yes`, load-or-verify semantics (atomic `nft -f` if the table is absent, exact-identity verification if present), no `ExecStop` flush (so stopping it never removes protection while packets could flow), and note that plain `Requires=` propagates a stop of the policy unit to the relay — which is the fail-closed direction you want, but it should be stated rather than discovered.
5. **Pin the config-mutation ordering against `switch_v2_locked`'s identity check.** The switch refuses cutover if `config.json` changes mid-transaction (`alpha.py:1114`, `alpha.py:1124`), and the currently deployed v8 alpha predates the `voice_turn` key, so its `config()` would reject a voice-bearing config. Therefore the voice object must be added only *after* successful pointer cutover to the candidate, never before or during; and rollback's "old binary receives disabled issuer config" should be worded as restoring the exact journaled previous config bytes (which are voice-free), not a `v:0` variant the old parser has never seen. The draft's phase 3 leaves this ordering implicit; make it explicit.

Two boundedness confirmations rather than findings: effective nft/UFW packet tests cannot run on the shared development host — an nft table is host-global state, i.e., a shared firewall change the audit correctly excludes — so they stay NOT RUN until a genuinely disposable environment exists; and phase-4 relay activation cannot be rehearsed locally at all (below), so the local rehearsal covers phases 1–3 and 5 plus rule *rendering* only, with relay activation recorded as its own named NOT RUN gate.

**Exact runtime rehearsal remains unavailable.** The production relay contract pins `User=paranoid-turn`, `/run/paranoid-turn`, `listening-ip=157.180.49.125` and the template hash inside `runtime.py:101`; rehearsing that exact unit locally would require either production identities on a shared host (not authorized) or a modified template — which, as the capability audit correctly states, changes the tested contract and must never enter production evidence. A fixture-profile TURN artifact with its own pinned template is legitimate but must be labeled as fixture evidence, and even it stays out of scope locally while relay runtime work remains a NOT RUN gate. Messaging-side rehearsal via loopback fixtures is available; the production-profile end-to-end rehearsal is not.

## B. Inert no-network LoadCredential/lifecycle slice — APPROVE with conditions

The concrete plan in `runtime-capability-audit.md` ("Concrete inert slice") is legitimate, distinct from the denied work, and well bounded. It runs no coturn, opens no sockets (`RestrictAddressFamilies=AF_UNIX`, `SystemCallFilter=~@network-io`), touches no firewall, ACL, namespace or shared unit, creates only uniquely named transient units via `systemd-run --collect` under existing identities (codex for both managers; no `paranoid*` names, no new OS account), uses freshly generated disposable secret material with digests kept out of evidence, requires `LoadState=not-found` preflights, and restricts cleanup to exclusively created names and paths. It does not retry the `media_discovery` worker in any form, and — correctly — it draws no conclusion about prohibited syscalls from that worker's opaque platform error. What it would prove (real system- and user-manager LoadCredential delivery, descriptor/mode/content properties, start/restart/stop lifecycle, missing/malformed-source failure) is genuinely new evidence the offline suites cannot supply, and the audit is already honest that it proves nothing about coturn, the production relay unit, expiry, ACLs or rotation.

Conditions of approval: keep the plan's own rule that an unsupported confinement property is reported as an exact refusal and stops that slice rather than being weakened; treat the world-writable `/var/tmp` parent carefully (exclusive `mkdir` at 0700 with post-creation `lstat` ownership verification, which the plan implies); no retry loops on failure — one bounded run per fixture name, evidence preserved; and the results must never be cited as relay-unit, CLI-closure or TURN-lifecycle evidence. Item 4 of the broader slice (installer plan/preflight/state-machine tests on modern v2 fixtures) is likewise fine as offline/loopback work, with any real messaging socket kept as the separate explicit scope the audit already declares. TURN-RT01, TURN-ACL02 and relay lifecycle remain NOT RUN, and root should stop any concretely denied action as stated.

## C. CALL-CONNECT01 — CONDITIONAL

**Accept the two-question split.** The historical first cause is unrecoverable: no retained trace exists, and no finite number of successful calls can retroactively identify it. CALL-CONNECT01 therefore stays OPEN as an explicit unknown — not waived, and with no impossible retrospective proof demanded. That is a permanent evidentiary fact, not a blocker on a different, honestly-scoped claim.

**Disposition on the matrix: yes.** The finite 3-scenario installer-integration matrix (fresh synthetic install with first microphone grant, incoming ≥30 s connected decoded audio; retained-permission redial, same bound; one outgoing call on the same candidate) **may establish current-build functional acceptance while the historical issue remains open**, provided: the scenario count is frozen before execution; product deadlines are used with no synthetic 15/20-second cutoffs and no consent-clock resets; every outcome is preserved and any real unexplained failure stops the matrix; full source/artifact/driver/observer provenance is retained with installed-identity limits honestly marked (file hashes are not loaded-code attestation); and it runs against the coordinated installer in the owned disposable environment once the relay gates pass — which also means it is currently queued behind those blocked gates, not runnable today. The evidence base justifying this framing is real and current-engine-exact: the baseline arm's natural SDK `connection` failure at 16.496 s with 23.357 s budget remaining, the fixed arm's connect at 0.904 s with relay/relay DTLS Opus and clean teardown, and the retained publication-regression record showing an incoming call with decoded media observed to ~59.8 s and completion at ~80.6 s — well beyond the historical failure window. Record the acceptance under its own finding/ID; do not convert CALL-CONNECT01 itself to PASS.

**The source-time seam is not necessary before the matrix.** The matrix's pass criteria (connected callback, committed-answer/setRemote at the host, sustained decoded-sample/energy growth, clean teardown) are all observable with the already-reviewed observer and host evidence; the seam adds value only when a failure needs causal attribution. The proposed constructor-injection design is technically correct about the gap — `WebRtcAudioEngine.fail()` closes and cleans before listener delivery (`WebRtcAudioEngine.java:382-386`), the ICE-connection callback is empty and the observer is unreplaceably passed at creation (`:340-361`) — so it is the right design *when needed*. Disposition: defer it; if any matrix run yields a real unexplained failure, stop, then implement the seam with genuine RED/GREEN, a fresh same-signer versionCode above 10, and verification that the sink is absent from the production APK, before further diagnostic runs. Spending a product version on it now, absent a demonstrated failure, is not justified. **Another identical short A/B is declined** — it cannot close the source-time gap and would only duplicate existing evidence.
