## Findings

| ID | Sev | Location | Issue |
|----|-----|----------|-------|
| ORCH-1 | Low | `local.py:116-121` | Remote stdout/stderr is captured unbounded into memory and persisted into the action record **before** the 128 KiB bound check fires; a hostile/verbose remote can bloat the local evidence record (the bound only flips the exit code afterward). Scenario: compromised host floods `status` output. Minimal fix: truncate to 131072 bytes before `record.update` (or check length first). Test: patch `subprocess.run` to return >128 KiB stdout; assert stored record is truncated and exit is 1. |
| ORCH-2 | Low | `remote.py:365-376` | The worker's lock probe proves *someone* holds the lock and the fd matches the inode, but not that the worker's own inherited descriptor is the holder (a third-party holder with an unlocked inherited fd would pass). Unreachable via `start()`, which is the only spawner. Minimal fix: `fcntl.flock(lock_fd, LOCK_EX | LOCK_NB)` directly on the inherited fd (no-op if held by this open file description, raises if held elsewhere). Test: third process holds lock, worker fd unlocked → must refuse. |
| ORCH-3 | Info | `local.py:64-72` | Gate validation confirms the two Fable results are *successful runs* but cannot parse their disposition — a review whose text says BLOCKED still hashes as a valid result file. Protection is solely the parent's manual `all_blockers_resolved: true`, which is the disclosed design; no code change required, but the parent must read both result texts, not just bind hashes. |

All three are independently resolvable/acceptable at parent discretion; none blocks gate creation on its own — ORCH-1/ORCH-2 fixes would change script hashes and require re-freezing the manifest, so fixing versus accepting is the parent's call, documented in the gate.

## Nonblocking risks / NOT RUN

- **Nothing has executed against the live host.** Specifically not run: the live old binary's `self-service-capabilities` response (wrapper requires exactly `runtime: self-service-v2-exact-ip-v1` + schema hash ff401a46… from the *old* binary 3418332f…, which is only indirectly evidenced); failure mode is safe refusal before any mutation.
- **Neighbor strict equality is fail-closed but brittle**: the frozen nginx/docker/postgres PIDs and monotonic start timestamps date from 2026-09-09T19:17Z. A benign neighbor restart before start refuses safely; one occurring *between* controller success and postflight would leave a genuinely-updated healthy service marked `failed_or_unconfirmed` with no in-band path to a confirmed-success record — owner manual inspection, by design.
- **No wrapper timeout on the controller** (`remote.py:392`): controller deadlines are mostly bounded (`wait_health` ≈ ≤520 s), but the `systemctl stop/start` calls at `alpha.py:1101-1114` have none; a hung systemd job leaves durable state `running` with `matching_worker_alive` reported by `status` — never auto-repeated, owner inspects.
