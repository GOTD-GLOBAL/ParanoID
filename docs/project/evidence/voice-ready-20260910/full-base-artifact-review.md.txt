## C1 (required, blocking this run). The guest will hang in systemd's First Boot Wizard.

Observed, not inferred:

1. `etc/machine-id` is in the image with **size 0** (mode 33060). PID 1 treats an empty machine-id as first boot and creates `/run/systemd/first-boot`, so `ConditionFirstBoot=yes` is **true**.
2. `usr/lib/systemd/system/sysinit.target.wants/systemd-firstboot.service` is present — statically enabled, unaffected by presets.
3. I read the shipped unit: `ConditionPathIsReadWrite=/etc` (true on the tmpfs rootfs), `Before=sysinit.target`, `Type=oneshot`, `StandardInput=tty`/`StandardOutput=tty`, `ExecStart=systemd-firstboot --prompt-locale --prompt-timezone --prompt-root-password`.
4. `etc/localtime` is **absent** from the manifest while `usr/share/zoneinfo/zone1970.tab` is **present** — so the timezone step is not skipped as "already configured" and has a full list to prompt from.

Consequences: `Type=oneshot` has no default start timeout, the prompt reads `/dev/console` → `ttyS0`, and `-chardev file` never delivers input or EOF, so the read blocks indefinitely. Because the unit is ordered `Before=sysinit.target`, `basic.target` is never reached and `voice-fixture-base.service` never starts. The run ends at the 600 s host wall as `GUEST_PREREQUISITES_FAILED`/`TimeoutError`, with no `VOICE_BASE_RESULT`, consuming the single authorized boot. (`--prompt-locale` will likely self-skip: no `etc/locale.conf` and no `usr/lib/locale/locale-archive`. `--prompt-root-password` should skip on the generated `etc/shadow` root entry. Neither rescues the timezone prompt.)

Two acceptable fixes; either is cheap, neither weakens a guard:

- **Boot-source only (no rebuild):** add a documented systemd kernel-command-line mask for `systemd-firstboot.service` to `-append`. Confirm the exact option spelling against the systemd version actually shipped *in this image* (its own `kernel-command-line` documentation), since I cannot execute. First-boot stays true, so PID 1 will run a preset-all pass — harmless in a disposable guest, a few seconds. This changes `boot_source_sha256`, so the freeze, the dropper's embedded literal and a short re-check of that diff must follow.
- **Rebuild (more robust):** emit a valid 32-hex `/etc/machine-id`, an `/etc/localtime`, and a `/etc/systemd/system/systemd-firstboot.service → /dev/null` mask. This requires the owner to authorize a **second** assembly and a fresh artifact review of the new image; the current image and its receipt would be superseded, not reused.

I have no preference forced by safety; the cmdline fix preserves the one-assembly discipline and the already-verified image bytes.

## C2 (fix if you rebuild; otherwise accept and record)

`voice-fixture-base.service` sets `TimeoutStartSec=300`, but the guest script's own permitted budget is larger: 30 + 30 + 60 (pam) + 90 (depmod) + 10 × 30 + 30 (accel probe) ≈ 540 s. If the worst case materialises, systemd SIGTERMs the script, the `finally` block never prints the receipt or powers off, and the host wall consumes the run anyway. Expected real runtime is well under 300 s, so this is a documented single-shot risk, not a blocker — but it is inside the image, so it is only fixable on a rebuild.
