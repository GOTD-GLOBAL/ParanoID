# Verdict: **CONDITIONAL**

The two structurally hardest things are done correctly. Correction 6 is genuinely implemented in code, not by convention: `FULL_REHEARSAL_PROFILES` is still `frozenset()`, `apply` raises `FullRehearsalUnavailable` before any mutation, and `verify_rehearsal` resolves real root-owned bytes, verifies the fixture kit through `verify_kit`, requires `fixture['components'] == production['components']` and byte equality across `BASE_FILES | RELAY_FILES`, and rejects hash-only logs. Correction 7 is implemented as a genuinely distinct `boundary()` requiring root — the inverse of `fixture_boundary` — and `vm_boundary` is called on **all five** dispatch points (`preflight`, `apply`, `status`, `rollback`, and via `state_record`'s profile branch). Non-circularity holds: `GATES[VM_FIXTURE]` contains no rehearsal gate, so `validate_acceptance` never re-enters `verify_rehearsal` for the fixture. The legacy message-only fixture is untouched: `relay_profile` excludes it, so no secret, no relay component, no network module. `VM_FILES` is excluded from production kits by `verify_kit`'s exact-membership rule. Path containment on case logs (`[a-z0-9][a-z0-9-]{0,80}\.json`, no separators) is correct.

Ten corrections are required before this is fit to carry a rehearsal.

## Required

1. **`isolation_sha256` is a tautology.** In `boundary()` it is only `is_hash`-checked; nothing derives it from `observe_guest`. `apply` then requires `acceptance[...]['evidence_sha256'] == boundary['isolation_sha256']` — i.e. the receipt must match an arbitrary constant the boundary file asserts about itself. `boot_id` is genuinely bound to `/proc/sys/kernel/random/boot_id`; isolation is not bound to anything. Compute `sha(canonical(normalized_observation))` inside `boundary()`, require the record to equal it, and return the computed value. This is the single largest gap in the new code.

2. **The rehearsal binds code bytes but no configuration.** `verify_rehearsal` proves the fixture and production kits share implementation bytes and component identities, but nothing constrains *what was configured* in the guest. A rehearsal run with a different `message.user`/`uid`/`root`/`unit`, a different `relay` identity, or a different `mode` coverage passes. Require the report to embed the fixture intent, and assert its `ip`, `message` and `relay` blocks equal the production intent being applied, differing only in `profile` and `interface`. Optionally recompute the fixture plan hash from that intent plus the fixture kit as a self-consistency check.

3. **Five production gates remain hand-authored hashes despite file-bound evidence existing.** `REQUIRED_CASES` contains `issuer-interoperability`, `turn-rt01`, `turn-acl02`, `relay-cli`, `relay-credentials-lifecycle` — the same names as production gates whose acceptance entries are still `{result: PASS, evidence_sha256: <hex>}` with nothing resolved. Bind them: for each production gate with a matching case name, require `gates[name]['evidence_sha256'] == report['cases'][name]['sha256']`. This converts five more gates from assertion to artifact at near-zero cost.

4. **Corrections 5 and 8 lost their observable keys.** Corrections 1–4 survive as required check keys (`namespace_match`, `positive_controls`, `local_out_of_range_denied`, `same_host_in_range_media`) plus the `client_route` unicast test. But nothing in `REQUIRED_CASES` obliges the runner to record the pre-address-assignment NIC-less/link inventory, the teardown loopback-only/no-route re-assertion, or the UFW loopback-`ACCEPT`-first and exact single TCP38443 prerequisite. Add explicit keys; otherwise those two corrections are enforced only by prose.

5. **`test_production_apply_cannot_accept_a_hash_only_receipt` proves nothing.** With `FULL_REHEARSAL_PROFILES` empty, `validate_acceptance` raises `FullRehearsalUnavailable`, a `ValueError` subclass, before any file binding runs. The test would pass with `verify_rehearsal` deleted. Patch availability as `RehearsalFilesTests` does, and assert the failure is *not* `FullRehearsalUnavailable`.

6. **`assertNotIn(PRODUCTION, frozenset())` is vacuous.** Assert `FULL_REHEARSAL_PROFILES <= {VM_FIXTURE}` so the invariant still holds once the set is populated. Add a direct test that `verify_kit` rejects `single_host_vm_runner.py` inside a `PRODUCTION` kit.

7. **Root-ownership enforcement is stubbed out in every test.** `RehearsalFilesTests` overrides `read_file` to force `owner=geteuid()` and replaces `verify_root_kit` with a reader loop — which is precisely the assertion that failed in `full-vm-profile-green-attempt1.log`. The result is that no test exercises `owner=0` on the report, the case logs, or the fixture kit. Add a recording stub asserting `owner=0` is passed on every evidence read and that `verify_root_kit(fixture_root)` is invoked. Keep the honest comment, but the comment currently understates what is unverified.

8. **Guest observation hardening.** `observe_guest` reads DMI product and boot id with bare `Path.read_text()` — unbounded, symlink-following, and blocking if `/sys` is overmounted; use a bounded `O_NOFOLLOW|O_NONBLOCK` fd read with `fstat` (`read_file` cannot be used directly because `/sys/class/dmi/id` is itself a symlink). The PCI class-0x02 scan misses virtio-mmio and USB NICs: additionally require that no `/sys/class/net/*/device` exists. Enumerate namespaces and require exactly `{vr-client}`, since only the initial namespace and `vr-client` are inspected today. Finally, `BOUNDARY.lstat()` re-resolves the path after `read_file` already opened it; check the 0400 mode on the same descriptor.

9. **`interface` still admits a leading `-`/`.`** — `r'[A-Za-z0-9_.-]{1,15}'`. The VM path is safe because it is pinned to `vr-relay`, but the production path is not, and the original correction 8 explicitly asked for `[A-Za-z0-9][A-Za-z0-9_.-]{0,14}`. `ip ... show dev -eth0` fails closed; the rendering of this string inside `single_host_network.py` is **unassessed** because that file was not supplied.

10. **Move the production root check to the top of `apply`.** Today `validate_acceptance` — which loads and executes `single_host_vm.py` from the kit — runs before `if production and os.geteuid() != 0`. Also use `Path(api.__file__).resolve()` in `boundary()`; `read_file`'s `O_NOFOLLOW` will otherwise refuse a symlinked controller path outright.

## Notes, not blocking

`plan()` hashes `full_rehearsal_profiles`, so a receipt cannot be carried across the availability change — good, and worth stating in the runbook. Because `verify_rehearsal` demands byte-identical `single_host.py` between kits, the guest necessarily runs with production availability already open; after that build ships, the verifier is the *only* remaining barrier on the host, which is exactly what corrections 1–3 above are protecting. `boundary()` requires the running controller and all its ancestors to be root-owned, so the guest bootstrap must invoke the coordinator from an extracted root-owned kit, not a worktree — document that precondition. Receipts have no freshness field; state explicitly that they do not expire. Reporting is otherwise faithful: the RED log and the failed GREEN attempt are retained and the final run is recorded as 10 tests OK — but the count moved 8 → 10 between them, and the intervening attempts are not in the bundle; retain them too.
