### Blocking issues — the instrument cannot measure its own stated unknown

**A‑1. A non-44-byte or absent ACL destroys the entire observation, including the file.** (`:48-51`)

```python
n = getter(fd, b'system.posix_acl_access', buffer, 44)
if n != 44:
    raise ValueError()
```

`bounded-scope.md:12-13` states the remaining unknown is "file and credential-directory ACL shape, especially directory 0550 versus 0750", and the prior Opus review's sharpest finding was that the directory branch is probably mis-specified. This code hard-rejects any shape other than exactly five entries. Concretely:

- If systemd took the **chown fallback** (no ACL on the copy — the ACL-free path the prior review said should remain *primary*), `fgetxattr` returns `-1/ENODATA` → `ValueError` → the run yields nothing. The stat block that would have shown `uid == euid, mode 0400` — i.e. "the existing `read_secret` already accepts this and no new reader is needed" — is discarded.
- If the directory ACL has 4 or 6+ entries, same total loss.
- Because `:58` builds the dict left-to-right (`'directory':snapshot(directory),'file':snapshot(credential)`), a **directory** surprise also destroys the **file** observation — the one shape the prior review considered self-consistent and on which the Gate 2 reader depends.

"Reject unsupported shape and stop" is the correct rule for the **runtime reader** (Gate 2). Applying it to the **measuring instrument** is a category error, and under the no-repeat rule it burns the single authorized observation for zero information.

Required change: keep the buffer fixed and bounded, but make shape a *recorded numeric outcome*. Use a fixed `68`-byte buffer (header + up to 8 entries), accept any `n` where `n >= 4 and (n-4) % 8 == 0 and n <= 68`, decode `(n-4)//8` entries, and emit `acl: {version, entry_count, entries}`. On `n < 0`, emit `acl: null` plus `acl_errno: <int>` and still return the full stat block. `parse_observation` (`:89`) must then accept `1 <= entry_count <= 8` and any bounded int `version` rather than hard-requiring `version==2` and `len(entries)==5`. Output stays purely numeric and bounded; nothing is widened at runtime.

**A‑2. `use_errno=True` is set but `ctypes.get_errno()` is never called.** (`:41`) Distinguishing `ENODATA(61)` / `ENOTSUP(95)` / `ERANGE(34)` is exactly the difference between "chown fallback taken", "filesystem has no ACL support", and "larger ACL than expected". Record the errno as a bounded integer.

**A‑3. The helper's failure envelope is computed and then thrown away.** The helper prints `{'v':1,'error':'METADATA_MEASUREMENT_FAILED','stage':stage}` and exits 1 (`:61-63`), but the parent only parses stdout when `returncode == 0` (`:137-142`) and stores only `error='unit_or_measurement_failed'`. With `--collect` the unit is garbage-collected, so no manager-side `Result=`/`ExecMainStatus=` survives either. A failed one-shot therefore yields **an exit code and nothing else** — and cannot be retried. This is a regression against a lesson already paid for: the earlier attempt "lost helper output" (`voice-single-host.md:151-153`), which is why the prior diagnostic added stage/descriptor reporting (`result.json:23-36`). Parse the failure envelope through a strict allowlist (`{v, error, stage}`, `error` a fixed literal, `stage` from a closed enum) and record it.

**A‑4. `stage` granularity is too coarse to localize a failure.** (`:40-58`) All ancestor validation, both opens' metadata work, both ACL calls and both rechecks collapse into `stage='metadata'`. Split into `directory_stat`, `directory_acl`, `directory_recheck`, `file_stat`, `file_acl`, `file_recheck`. Cheap, and it is the difference between an interpretable and an uninterpretable one-shot.

**A‑5. The synthetic source descriptor is never verified or recorded.** `create()` (`:121`) passes mode to `os.open`, which is masked by the **process umask** — never set explicitly anywhere in this script. Under a restrictive root umask, `helper.py` would land at `0400` and be unreadable by codex; the direction is always fail-closed, so this is not a privilege issue, but the delivered-copy observation is only interpretable relative to a known source shape (root-owned, `0400`, regular, `nlink 1`, 64 bytes). The prior diagnostic recorded exactly this (`result.json:17-22`); this script records nothing. Add `os.umask(0o022)` at entry, `fstat` the fd inside `create()`, and write the numeric source descriptor into the report before the unit starts.

### Non-blocking findings, worth fixing in the same pass

**A‑6. Root-to-codex TOCTOU on the evidence path.** (`:98-99`) `evidence.resolve()==evidence` plus `evidence.stat()` is a path-based check followed by a path-based `mkdir`/`chown` as root. A swap of a component between check and use would have root create and chown a directory elsewhere. The helper already demonstrates the right discipline; apply it here: open the evidence directory `O_DIRECTORY|O_NOFOLLOW`, `fstat`-validate ownership, then `os.mkdir('metadata-runtime', dir_fd=…)` and `os.chown(…, dir_fd=…)`.

**A‑7. Evidence file is world-readable and the tmp path can wedge saving.** (`:106`) `tmp.open('x')` uses default `0666 & ~umask` → typically `0644`. Contents are numeric plus argv (no secret), but there is no reason for it to be world-readable. Worse: if an exception occurs between `open('x')` and `os.replace`, the stale `.result.tmp` makes **every subsequent `save()`** raise `FileExistsError`, including the one in `finally`. Use `os.open(..., O_WRONLY|O_CREAT|O_TRUNC, 0o600)` or unlink-first.

**A‑8. The `finally` block can abort mid-cleanup and lose the most security-relevant outcome.** (`:146-159`)
- `show()` raises `'manager read refused'` on an unexpected `systemctl` return (`:116`). Called at `:148`, `:150`, `:158`, a transient failure propagates out of `finally`, so `shutil.rmtree(root)` never runs and the fixture — including the synthetic secret — is left on disk with no record.
- `:155` raises `'fixture root changed; refusing cleanup'` **inside** `finally`. Refusing the `rmtree` is right; aborting before `fixture_sources_removed`, `neighbors_after` and `save()` is backwards — tampering with the fixture root is precisely the outcome that must be persisted. Record `fixture_root_tampered: true`, `save()`, then surface it.

Wrap each cleanup step individually so cleanup always attempts fixture removal and always writes the final report.

**A‑9. Manager-side evidence is strictly weaker than the approved prior run.** `SHOW` (`:72`) is six properties; the prior diagnostic recorded 25, including `NoNewPrivileges`, `RestrictAddressFamilies`, `SystemCallFilter`, `User`, `Group`, `Result`, `ExecMainCode/Status` (`result.json:108`). Post-`--collect` readback returns defaults and is worthless (visible at `result.json:44-64`), and `--quiet` (`:131`) suppresses the invocation-ID line the prior run captured. Net effect: **"confinement unchanged" is supported only by the argv this script constructs, not by any manager readback.** That is acceptable — the helper never runs network code — but the artifact must say so. Add `"confinement_effectiveness": "NOT_PROVEN_REQUESTED_ONLY"` to `report` (`:102`) rather than leaving it only in `bounded-scope.md:28-29`; the JSON is what gets cited later. Add `InvocationID` to `SHOW` for a durable manager-side handle.

**A‑10. Remove `StandardError=inherit` (`:70`).** `--pipe` (`:131`) already connects all three streams; a redundant explicit property adds avoidable startup-shape uncertainty, and under the no-retry rule any avoidable startup failure burns the one permitted run. Behaviourally the current code is safe either way — stderr is captured by `subprocess.run` and never written to the report (`:110`, `:140`), which is the correct redaction.

**A‑11. Documented deviation, not a defect:** `report['commands']` and `planned_command` record the fixture credential **path** (`:132`), which `bounded-scope.md:27` nominally excludes. It is the synthetic `/var/tmp` fixture path, never a production credential path, and it is necessary provenance. Flag it explicitly in the scope string so the record is not challenged later.

**A‑12. Test-suite gaps.** The six tests pass (`metadata-offline.log`) and the AST guard (`test_measure_credentials.py:25-28`) is a useful tripwire, but it checks attribute *names* only — it would not catch `os.pread`, `mmap`, `os.sendfile`, or a rebound name. The real assurance is human reading of the 50-line frozen `HELPER`, which I did. Missing: no test for absent/short/long ACL handling (because it aborts — add with A‑1), no test of the failure-envelope parse (add with A‑3), no test that `version != 2` is handled, and no extracted/unit-tested form of the `run()` guards or the ancestor predicate. Add these as RED cases before the run.

### Concrete changes required before acquisition or boot

**B‑1 (sharpest). The VM is disposable; its host is not.** B as written puts a multi-GB image download, a package tree, and QEMU disk writes on `157.180.49.125` — the live host running nginx, the retained PostgreSQL cluster and the messaging alpha. `bounded-scope.md:50` says "No production host operations", but downloading and materializing several GB *is* an operation on that host, and filling the filesystem backing a retained production database is a real availability risk to data the project has repeatedly committed to preserving (`voice-single-host.md:31`). Required: (a) explicit owner authorization for **outbound HTTPS** to `archive.ubuntu.com`/`cloud-images.ubuntu.com` — the current authority record covers a bounded *inbound* port scope and a conditional install, not arbitrary egress; (b) a preflight free-space check with a stated margin and a hard total-byte budget; (c) confirmation that the evidence directory is not on the filesystem backing PG data, or an explicit quota; (d) cleanup-on-failure of partial downloads.

**B‑2. Name the full signature chain, not "SHA256".** `bounded-scope.md:46-51` says "verified against locally signed apt index SHA256" and "verified release manifest/signature". A hash checked against an index fetched from the same place is circular. Required, recorded at every level: pinned Ubuntu archive key fingerprint (`F6ECB3762474EDA9D21B7022871920D1991BC93C`) and the cloud-image signing key, `gpgv --keyring <pinned>` over `InRelease`/`SHA256SUMS.gpg`, then `InRelease → Packages` hash, then `Packages → each .deb` hash, then `SHA256SUMS → .img` hash. Record all four levels plus the keyring's own hash. State plainly that the host keyring is the trust anchor.

**B‑3. The extracted binary keeps every network backend; argv is the only control.** Ubuntu's `qemu-system-x86_64` is dynamically linked and links slirp. `-nic none` is a configuration choice, not a capability removal. Therefore: the shared-library closure is part of the TCB and every resolved library must be hashed and recorded (running from an extracted tree means `LD_LIBRARY_PATH`, which must point only inside the owned tree); and argv verification must read `/proc/<pid>/cmdline` of the **running** process (NUL-separated, exact), not the intended string. Add `/proc/<pid>/fd/*` enumeration asserting no `socket:[…]` descriptors and no `/dev/kvm`.

**B‑4. Resolve the monitor contradiction.** `bounded-scope.md:57-61` demands a "QEMU device inventory" but permits only serial stdio and forbids a TCP control listener. `info qtree`/`info network` require a monitor. Either add an owned **AF_UNIX** QMP socket inside the evidence directory (`-qmp unix:<owned>,server,nowait` — a local socket, not a network NIC, consistent with the stated ban on TCP control), or drop the device-inventory claim to "argv + guest-side observation only". Left unresolved, this stalls at execution time.

**B‑5. `-nodefaults` removes the serial device too.** Specify the full set explicitly: `-nodefaults -no-user-config -display none -serial stdio -monitor none` (plus B‑4's QMP), `-machine q35,accel=tcg -accel tcg` — never `kvm:tcg`, which silently uses KVM if permissions change. `-no-user-config` correctly suppresses `/etc/qemu/*.conf`, which can inject netdevs; additionally assert the extracted `qemu-bridge-helper` is not setuid and is never invoked.

**B‑6. The device denylist is missing vsock.** `bounded-scope.md:55-56` bans netdev/tap/bridge/slirp/guest-agent/9p/USB passthrough but not **`-device vhost-vsock-pci`** — a host↔guest channel that "no NIC" does not cover. Add explicit prohibitions on vhost-vsock, `-fsdev`/`-virtfs`/virtiofsd, `usb-net`, and any `-chardev socket` pointing outside the owned directory.

**B‑7. Disk and seed specifics.** Base image `0444` and never a writable backing target — use an explicit overlay (`qemu-img create -f qcow2 -b <base> -F qcow2`) or a copy; attach seed/package media `readonly=on`. The NoCloud seed must set `network: {config: disabled}` in meta-data and `datasource_list: [ NoCloud, None ]` via a `cloud.cfg.d` fragment, so cloud-init never probes `169.254.169.254`. No host SSH keys, no host `authorized_keys`. Guest assertions should be non-interactive `runcmd` output to `/dev/ttyS0` (`ip -o link`, `ip route`, `/sys/class/net/*`, `/sys/bus/pci/devices`), not interactive serial parsing. Add a hard wall-clock timeout — TCG boot of 24.04 at 2 vCPU/2 GiB is slow, and the process must be finite by construction, matching A's discipline.

**B‑8. Structural warning: a NIC-less VM cannot host the tests this is ultimately for.** TURN-ACL02 and effective own-host port denial require actual packets. A guest with zero network devices proves isolation and nothing else. The eventual suite will need either two guests joined by an owned `-netdev socket` pair — which **is** a host TCP listener and contradicts the current no-TCP rule — or a single guest exercising loopback/dummy interfaces with guest-only nftables. Decide which now, so B is not built into a dead end. Both remain unapproved and require their own review of exact fixture and test source before execution, exactly as `bounded-scope.md:66-68` states.
