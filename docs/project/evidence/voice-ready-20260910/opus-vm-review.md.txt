## Boot — required

**BOOT‑1. Tooling receipt not bound to the freeze.** `boot:100-104` trusts `result.json` content and hashes the receipt (128) but never compares `tools['source_sha256'] / ['plan_sha256'] / ['chain_sha256']` to the freeze entries. Add the three equalities — without them "reviewed exact source" holds for the boot script only.

**BOOT‑2. Failure destroys the evidence it exists to collect.** The fd inventory (166‑172), actual argv (160‑161) and Uid/CapEff (162‑164) all raise *before* the assignment at 175, so an `ISOLATION_FAILED` record names an error string but not the offending descriptor, argv or uid. Under one-run/no-repeat-to-green, assign into `report` and `save()` before raising.

**BOOT‑3. Console evidence recorded only on success.** `serial_sha256` is set at 185 after a strict decode; a `UnicodeDecodeError` at 184, or any earlier failure, leaves no console hash. Hash the file in `finally` and record decode errors instead of aborting on them.

**BOOT‑4. The IPv6 claim can be vacuous.** The guest emits `ipv6_route` only if the file exists (init:36); with IPv6 off, the section is empty and the loop at 81‑82 asserts nothing while the report still reads `default_external_routes: False`. Emit an explicit `ipv6_route=absent|present` marker and require one.

**Recommended.** BOOT‑5: put the limit in the JSON, not only the scope prose — add `"isolation_claim":"OBSERVED_POINT_IN_TIME_NOT_ENFORCEMENT"` and `"fd_inventory_scope":"PRE_CONT_ONLY"` beside `relay_acceptance`; the receipt is what gets cited later. BOOT‑6: nothing drains QMP stdout after `cont`, so a full pipe would block QEMU and surface as a misleading `TimeoutError`; drain in the poll loop. BOOT‑7: an odd fd target such as `/memfd:…` would trip line 171 and abort a genuinely isolated run — keep the strict rule, but pair it with BOOT‑2 rather than loosening it. BOOT‑8: `set -eu` plus `$bb ip link set lo up` means a missing busybox `ip` applet aborts before the nonce; verify the applet in acquisition or tolerate its absence explicitly.

## Honest limits

No rendering is treated as enforcement anywhere: `-nic none`, `-sandbox on` and the sandbox options are requests to a binary that still links slirp and iPXE ROMs; what carries weight is exact running-argv equality, the pre-`cont` QMP/fd inventory and the guest's own output. A successful run means `ISOLATION_OBSERVED` at a point in time, nothing more. The five offline tests exercise the parser and cpio rules only — they say nothing about runtime isolation.
