## Verdict: **CONDITIONAL** — design is sound and measurement-supported; five concrete corrections before TDD

Reviewer context: fresh independent review, model ID `claude-opus-5` as reported by this runtime; record actual identity from modelUsage. Two read-only greps were used to close one specific gap (existing `check`-mode callers). No execution, no rerun, no delegation.

### What checks out

- **Decode arithmetic matches the observation exactly.** 4-byte LE version header + 5 × 8-byte `<HHI` entries = 44. Tags 1/2/4/16/32 = USER_OBJ/USER/GROUP_OBJ/MASK/OTHER; 4294967295 = `ACL_UNDEFINED_ID`; dir `mode 360` = 0o550, `type 16384` = S_IFDIR; file `mode 288` = 0o440, `type 32768` = S_IFREG, size 64. The single fixed 44-byte `fgetxattr` is fail-closed in both directions (larger value → ERANGE, smaller → length mismatch) with no size-discovery or realloc oracle.
- **Requiring the exact ACL rather than mode bits is necessary, not ceremonial.** With a named USER entry present, the group mode bits *are* the MASK, so 0550 alone would not show that the root group lacks r-x. `GROUP_OBJ=0` and `OTHER=0` are the real property, and the "gid need not be 0" reasoning is correct.
- **Fallback branch 2's "no ACL lookup needed" claim is correct.** With group and other mode bits zero (0500/0400), the mask is zero, so every named ACL entry has zero effective permission. That branch is genuinely safe without an ACL syscall.
- **Refusing runtime 0600, 0750, and mixed shapes is right.** A systemd read-only copy needs no write bit, and unobserved layouts must not be pre-blessed.
- **TOCTOU structure is correct:** single-component `dir_fd` traversal with `O_NOFOLLOW|O_DIRECTORY|O_CLOEXEC`, fds held, `fstat`/`fgetxattr` on descriptors, post-read recheck, no chmod/chown/setfacl/copy fixup, `≤65` bytes read against the existing exact-64-hex format. `CDLL(None, use_errno=True)` with symbol check and explicit `c_ssize_t` restype avoids both 64-bit truncation and any library-path search.
- **Evidence honesty is intact:** `relay_acceptance NOT_RUN`, `confinement_effectiveness NOT_PROVEN_REQUESTED_ONLY`, cleanup/readback true, neighbors byte-identical before/after, `stop` exit 5 is the expected already-collected transient unit.

### Conditions (resolve before writing tests)

1. **`baseline-guards.json` contradicts the design.** It pins a whole-file hash for `deploy/turn/runtime.py` (`e302d7…`), yet `main()` must change to require the exact production `CREDENTIALS_DIRECTORY`/`RUNTIME_DIRECTORY` and to call the new getter. Re-express that guard at function/AST granularity (as already done for `generic_reader_AST_sha256`) covering `read_secret`, `render_config`, `write_config`, `child_environment` and `TEMPLATE_SHA256`. Otherwise the final review sees a guaranteed false guard violation, or an implementer hides the getter elsewhere to preserve a hash.
2. **Check-mode restriction removes a documented, supported workflow.** `deploy/turn/README.md:60-62` prescribes an offline check with an *exclusively owned temporary credential directory*; the design makes exactly that fail. Decide and record one of: (a) check mode keeps the generic reader and explicitly does **not** validate the production ACL contract, or (b) the workflow is withdrawn and README plus any preflight caller change in the same commit. Grep shows `single_host.py:834` wires only `runtime.py run`; confirm `plan`/`preflight` has no `check` invocation before choosing (b).
3. **Branch selection must precede the ACL syscall.** Branch 2 has no ACL: `fgetxattr` returns ENODATA/EOPNOTSUPP. "Reject any error" must be scoped inside branch 1 only; select by `fstat` uid/mode first. As written, "one 44-byte call per descriptor / reject any error" can be read as unconditional and would break the preserved fallback.
4. **Do not over-pin observed directory constants.** Directory `size 60` and `nlink 2` are fixture artifacts of this tmpfs; only file `size 64` / `nlink 1` are contract. Directory size/nlink/ctime must be compared self-to-self across the recheck window, never to the observed literals.
5. **Add these negatives to the TDD list:** ERANGE from a 6-entry/52-byte ACL (distinct from a short return); named USER id ≠ euid; permuted-but-equal entry set; file MASK 5 instead of 4; **mixed pair** (branch-1 directory with branch-2 file and the reverse) must reject, since the design forbids mixed acceptance; and inode/ctime change between read and recheck.

### Residuals to state, not to mark PASS

- The measurement is one **transient** unit with `User/Group=codex(1003)`; production `paranoid-turn.service` is persistent with a static system user. Same systemd executor path, but not the same unit — the separately bounded no-network matrix must confirm the shape for the real unit/UID before artifact review.
- `O_NOFOLLOW` cannot prevent mount-point substitution at `/run/credentials/<unit>` (it is a separate tmpfs mount). Record this as residual root trust, do not claim it prevented.
- `alpha.py` keeping the generic reader is defensible — a **user** manager creates credential dirs as that user (uid==euid, 0400, no ACL) — but that is inference here. Include the inert user-manager case in the no-network matrix; do not assert it as measured.
- A systemd upgrade can change the credential ACL shape; the result is a fail-closed relay start failure. The runbook must give the exact diagnostic and require re-measurement plus re-review.

Nothing in this design requires reading credential bytes outside the production path, and it forbids production entry-point override in tests — credential compatibility is satisfied. This closes only the metadata fact.
