# Voice control v1

This is the single proposed contract for [RFC-0017](../rfcs/0017-voice-calls.md),
[ADR-0011](../decisions/0011-voice-calls.md), REQ-CALL-002–005. Written before
runtime changes. [Fresh design review and exact-doc closure](../project/evidence/voice-calls-20260909/README.md)
completed before implementation. The native control path and Java runtime now
implement this proposal. Real direct/isolated-relay media checks pass separately;
final application/artifact/source acceptance remains outstanding.

## Authentication and delivery

All controls use [first-contact-v1](first-contact-v1.md) mandatory signed frame2
and Olm `PlainV1`, with `kind: "call"`. The exact inner and wrapper account,
device, credential/contact fingerprint, realm/SPKI, channel and message ID checks
remain mandatory. The entire SDP is encrypted and signed. Java labels and relay
metadata never authorize a call. A call body from a sender absent in the original
committed contact map is rejected, discarding transient Account/ratchet/contact
changes. Blocked peers are rejected. Calls never upgrade contact trust.

Every accepted control persists the existing ratchet/cursor candidate
before emitting one transient authenticated event. Duplicate/rejected/failed-save
events emit nothing. Exact call redelivery is rejected by cursor/ratchet rather
than the text-specific exact-duplicate ledger. Call controls create no text, receipt or receipt commitment.
The core schema3 and sealed snapshot4 shape remains unchanged; no calls resume
from disk. Queued immutable ciphertext may be retried but never re-signed or
interpreted as fresh after its live call context is gone. Existing v8 rejects
unknown call bodies while its text path remains usable; exact interoperability
and old-code reopen tests are required.

## Strict body

The body has exactly these fields; unknown or duplicate fields are rejected:

| Field | Meaning |
| --- | --- |
| `v` | Integer 1 |
| `kind` | `knock`, `ready`, `offer`, `answer`, `heartbeat`, or `end` |
| `call_id` | Fresh canonical UUIDv4 generated for one explicit outgoing action |
| `caller_nonce` | Fresh random 32 bytes, lowercase hex, generated by caller |
| `callee_nonce` | Empty for knock and pre-ready end; fresh random 32 bytes generated in receiver readiness slot, echoed thereafter |
| `seq` | Integer 0 through 2147483647, monotonic per sender; knock/ready 0, offer/answer 1, later controls at least 2 |
| `sent_ms`, `expires_ms` | UTC milliseconds through Java Long.MAX_VALUE; positive, expiry later by at most 45000 ms |
| `sdp` | Nonempty bounded SDP only for offer/answer; empty otherwise |
| `fingerprint`, `ice_ufrag`, `ice_pwd` | SHA256 DTLS fingerprint and exact ICE fields from offer/answer SDP; empty otherwise |
| `offer_digest` | SHA256 of exact offer UTF-8 SDP for offer/answer and later controls; empty for knock/ready and pre-offer end |
| `reason` | Empty except end: `hangup`, `reject`, `cancel`, `busy`, `timeout`, `failed`, `unavailable` |

Maximum SDP 6144 UTF-8 bytes; whole decoded frame2 remains at most 16384 bytes.
An end before ready matches the live peer/call ID/caller nonce only. A receiver
may release its readiness-only slot on that empty-callee, empty-digest end while
its ready response is still in flight; no ringing or media authority is created.
An active call never accepts an empty callee nonce once ready was adopted. End after ready but
before offer carries both nonces and an empty offer digest. End after offer
requires both nonces and its exact offer digest. No empty-field fallback.
Canonical lower-case fingerprint is 64 hex digits with no colons. Only SHA-256
fingerprints are allowed. ICE ufrag/password are bounded RFC ICE tokens.
Complete SDP must describe exactly one active audio `m=` section with Opus,
DTLS-SRTP, RTCP mux, one fingerprint and one ICE context; reject video, data,
duplicate/conflicting fingerprint/ICE, invalid media directions and at most
16 candidates. Each candidate line is bounded to 512 bytes. The SDK receives
only validated exact authenticated SDP. No trickle or renegotiation in v1.

## Freshness, state and consent

Caller explicit call action creates call ID/nonce and sends knock. A known peer
may respond ready by creating an in-memory random callee nonce without any
microphone or PeerConnection. Limit 8 readiness slots, one per peer, with a
monotonic 45-second expiry; reject additional work when full. A ready is useful
only for the caller's matching live outgoing call. Offer is useful only for the
recipient's exact unexpired readiness slot and both nonces, then consumes it.
Restart destroys these slots and live calls, so old offers cannot ring even if
the clock moves backwards. First-seen expired controls are rejected as well;
wall-clock jumps terminate active negotiations rather than extend consent.

There is at most one ringing/negotiating/connected call. Occupied clients return
busy; simultaneous crossing calls both end busy without automatic answer or a
new microphone grant. At most 6 knock requests per peer/minute and 24 globally;
limits use monotonic time. Terminal IDs are retained in bounded memory through
the maximum live TTL; refuse new calls on full terminal capacity. Call controls add no durable Event rows, so heartbeats cannot exhaust the
1000-event text ledger. Below-cursor replays are refused; an already retained
Olm session must never be recreated from a replayed prekey after failed decrypt.
Ratchet replay rejection persists across restart; runtime nonces/state provide
the additional call-consent boundary. This correction requires a forged-higher-
sequence replay test and at least 20 simulated maximum calls followed by text.

The caller requests RECORD_AUDIO only from explicit call intent. Caller media
creation requires granted permission and matching ready. Incoming ringing never
creates media or requests microphone permission. Only an explicit Answer and
permission may create callee media. Reject/cancel/missed/timeout never capture.
Answer must match call ID/nonces and exact offer digest. Unexpected kind,
sequence, identity, stale callback generation or state cannot change live media.
Authentic transport success alone never displays Connected; actual WebRTC
connection state drives it. Call acceptance never means identity verification.

Ring/negotiation timeout is 45 seconds; ICE disconnection recovery is at most
10 seconds, then terminal failure. Each endpoint sends an E2EE heartbeat through
the authenticated relay every 10 seconds; no new valid peer heartbeat for
30 seconds terminates media. Confirmed local authorization failure or local
storage freeze terminates immediately. A signed-session request may use the
existing single retry after a first HTTP401: a pooled connection can lose a
response after nonce consumption, so retry the same immutable operation with one
fresh signed nonce. That first ambiguous rejection alone is not confirmed loss
of authority. A second HTTP401 terminates local call authority immediately;
authorization failures outside that existing retry path terminate immediately.
The retry does not reset heartbeat, negotiation or call-duration deadlines and
does not permit indefinite re-attestation. Later messaging reconnection cannot
restore ended call consent. Revocation cannot retract audio already sent;
peer detection is not instantaneous. Authorized pre-revocation controls may be
delayed up to their 45-second TTL, followed by 30 seconds of silence: worst-case
75 seconds plus allowed clock skew, not a strict 30-second revocation claim.
Receiver accepts no control dated more than 5 seconds in the future. A clock
change outside that tolerance ends the negotiation/call.
Maximum call duration 15 minutes, then terminate visibly. Calls do not consume
the text replay Event budget. Calls still advance the shared ratchet/cursor and
use retained server opaque storage; exhausted server storage is fail-clear and
never silently pruned or bypassed. Media/network work does not block text state.

On each resumed receive generation, the client first uses the existing signed
`messages` fetch to confirm current authenticated readiness, then returns to the
existing `events` long poll. The new generation is observed only after guarded
response processing and any required sealed commit. This changes request ordering,
not the wire contract, cryptographic checks or authorization requirements; no
optimistic connected callback is allowed.

Enqueue call controls only while the realtime lane is connected, with at most
one heartbeat awaiting actual server acceptance. A signal completion means
actual validated server acceptance after local durable commit, not merely a
successful save. Any enqueue failure terminates locally. Native call enqueue
requires fewer than 16 total pending envelopes for the peer, preserving the
remaining ordinary 400-envelope outbox capacity for text even across restart.
No backlog of heartbeats is created offline. Existing immutable queued frames
may finish a retry after expiry but never regain call authority; the receiver
drops expired controls and requires fresh runtime nonces. No unsafe deletion
or re-signing of durable ciphertext is introduced.

All terminal paths disable tracks, dispose PeerConnection/audio sources/factory
as owned, stop microphone foreground service, release audio focus/proximity,
restore routes/mode and cancel callbacks/timers. No default call recording.
Microphone foreground service begins only from visible user start/answer intent;
background incoming visibility uses an honest notification and requires opening
the app to answer. Opt-in messaging foreground service is not reliable Doze or
force-stop incoming-call delivery.

## Network and media boundary

Media uses endpoint DTLS-SRTP with the authenticated fingerprint. A TURN relay
forwards ciphertext and sees IP/timing/size; a future SFU needs separate true media
E2EE before any equivalent claim. Direct ICE exposes peer IP. No arbitrary public
STUN/TURN, hardcoded public relay password, new DNS or live listener is added.
An isolated local coturn fixture and prepared configuration may use synthetic
short-lived credentials; public deployment requires separate concrete review.
Network changes get the bounded SDK reconnection window; fresh call action is
required after failure. Seamless ICE restart is not implemented by this version.
